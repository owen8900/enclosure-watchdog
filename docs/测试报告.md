# 验证报告

本报告分两部分：**算法层验证（PC 端）**与**硬件在环验证（实板）**。
前者不依赖任何硬件，用 GCC 在 PC 上编译运行；后者在正点原子 MiniPro STM32H750 V1.5 上执行，
数据全部取自串口实测输出，未做推算。

## 验证方式

`code/App/` 下的模块不引用任何硬件头文件，只依赖 `stdint.h` 和标准数学库，
因此可以在 PC 上编译运行。验证用 GCC 11.4（WSL Ubuntu 22.04）完成：

```bash
cd code/pc_test
bash build_run.sh
```

测试程序为每个场景构造一段输入序列，逐步喂给状态机与诊断模块，
检查状态迁移和目标故障码是否与预期一致。每项断言打印期望值与实际值。

这类验证只能覆盖逻辑正确性。时序、噪声、采样误差、总线竞争等问题
必须上板之后才知道，对应内容见文末《硬件在环验证（实板）》。

## 场景 1：三级告警与迟滞恢复

**输入**：负载温度每秒上升 5°C，从 25°C 升到 80°C；再每秒下降 5°C 回到 30°C。
两路温度探头读数相差 1°C，不触发漂移判据。

**预期**：升温时 NORMAL → WARN → ALARM → EMERGENCY；
降温时按迟滞阈值反向迁回。

**实测**：全部按预期迁移。值得注意的是 WARN 的触发点。

温度在 t=5s 时达到 50°C，超过 45°C 阈值，但状态直到 t=7s 才切换为 WARN——
因为向上迁移需要连续 3 秒满足条件。这是去抖机制在起作用，
符合设计意图：单次超限不报警。

## 场景 2：加热回路断路

**输入**：占空比 50%，电流 0A，持续 3 秒。

**预期**：电流低于 0.05A 且占空比大于 0 的时长累计到 2 秒时，报 `加热回路断路`
并锁存。

**实测**：在 2.0s 处触发，与判据阈值一致。超时参数 `CFG_I_OPEN_MS` 单位是
毫秒，实际物理意义是"确认断路需要观察的时间"，设为 2000 是权衡结果：
设太短容易把瞬时的接触抖动误判为断路，设太长则断丝时加热已经停了很久。

## 场景 3：过流

**输入**：占空比 100%，电流 3.2A。

**预期**：超过 2.5A 立即触发，不经去抖。

**实测**：单步即触发。过流不设去抖是有意的——短路电流没有"观察"的余地。

## 场景 4：MOS 击穿直通

**输入**：占空比 0，电流 0.5A。

**预期**：报 `MOS 击穿直通`。

**实测**：单步触发。这个判据的工程意义在于：MOSFET 击穿后漏源短路，
即使栅极命令为低，回路仍然导通，加热不会停止。此时唯一的保护手段是
外部温控开关和保险丝，固件的责任是尽早发现并告警。

## 场景 5：温度探头漂移

**输入**：负载探头 70°C，局部探头 59°C，占空比 0。

**预期**：两路都超过 45°C 且偏差超过 5°C，报 `温度传感器漂移`。

**实测**：单步触发，偏差 11°C。

判断条件要求两路都超过 45°C 是有原因的：如果有一路是常温，
也有可能是那一路的探头坏了而不是这一路。要求两路都进入预警区，
是为了把"真实过热但两路读数有正常差异"和"探头失效"区分开。

## 场景 6：散热异常

**输入**：占空比 80%，电流 0.5A，温度每秒上升 2.0°C。起始温度 30°C。

**预期**：模型预测温升速率约 0.84 °C/s，实测 2.0 °C/s，残差 1.16 °C/s，
超过 0.5 °C/s 的阈值，报 `散热异常`。

**实测**：触发，实测温升速率 2.000 °C/s。

**这一版判据改过一次。** 最初写的是"温升速率超过 0.3 °C/s 就报警"，
结果场景 1 的正常升温（5 °C/s）直接触发了误报。
问题在于固定阈值没有物理依据——温升速率取决于加热功率和负载热容，
不是可以拍脑袋定一个常数的事情。

改成一阶热模型残差之后，判据比较的是"实测温升"和"由电流推算出的功率
所应产生的温升"之间的差异，不再依赖绝对的速率数值。

## 场景 7：元件老化趋势

**输入**：占空比 50%，电流恒定 0.5A，负载电压从 5.00V 以每步 0.01V 缓慢上升。
40 步之后 R 从 10.000Ω 升到 10.780Ω。

**预期**：阻值斜率超过 0.05 Ω/s 时报警。

**实测**：斜率 0.2000 Ω/s，触发 `元件老化趋势预警`。

判据只在"占空比大于 0 且电流大于 0.05A"时才计算阻值，因为占空比为 0 时
电压读数没有意义，强行算 R 会得到无意义的数值把趋势窗口污染掉。

## 场景 8：加热闭环

**输入**：一阶热模型 `C·dT/dt = P − k·(T − Tamb)`，C = 9 J/K，
k = 0.08 W/K，Pmax = 10W，环境温度 25°C，目标 50°C。仿真 200 秒。

**预期**：收敛到目标温度附近。

**实测**：

```
   时间(s)   温度(°C)   占空比(%)
        0      25.00      100.00
       20      45.35       93.25
       40      49.00       19.95
       60      49.04       19.24
      100      49.04       19.24
      180      49.04       19.24
```

稳定在 49.04°C，与目标相差 0.96°C。

这个稳态误差是纯比例控制的固有特性。比例控制要维持输出，就必须保留一个
非零误差。若要把误差压到 0.5°C 以内，需要引入积分项。

目前保留纯比例是有意的：积分项在故障注入测试中容易积累，一旦温度
被外部因素（比如人为拔掉加热线）拉低，积分器会因为长时间误差而饱和，
恢复时产生大幅超调。对温控这种响应慢的系统，超调比稳态误差更危险。
后续如果实测发现 1°C 的误差不可接受，再考虑加积分并配合抗饱和处理。

**关于参数 C 和 k**：这两个值目前是从 10W 水泥电阻的典型热物性估的，
不是实测辨识的。上板之后需要用恒定功率加热并记录温度曲线重新拟合，
否则判据 5 的残差基准不准，会直接影响误报率。这是上板后的第一项测试任务。

## 硬件在环验证（实板）

固件在开发板上随阶段推进逐项验证。以下数据均取自实板串口输出。

### 下载通道（P0a）

| 通道 | 方式 | 实测结果 |
|---|---|---|
| 串口 | USB_UART（CH340）+ BOOT0 接 3V3 + 按一次复位，115200 8E1 握手 | 通过，`0x7F` 回 `0x79` |
| SWD | ST-Link V2 四线（SWCLK / SWDIO / GND / 3.3V），BOOT0 接 GND | 通过，Keil 读到 IDCODE `0x6BA02477` |

SWD 板侧接线（20 针座）：pin9 = SWCLK、pin7 = SWDIO、pin4 = GND、pin2 = 3.3V（pin1 与 pin2 同为 VDD）。
下载日志为 `Erase Done` → `Programming Done` → `Verify OK` → `Application running`。
接入 SWD 后 BOOT0 永久保留在 GND，不再需要跳线。

### 上电自检（P0a）

USART1 以 115200 8N1 打印自检信息：MCU 型号、SYSCLK / HCLK / PCLK1 / PCLK2 实际频率、
串口参数与 RGBLED 状态。实测频率与时钟树设计一致：SYSCLK 480MHz、HCLK(AXI) 240MHz、APB1/2 120MHz。

RGBLED（红 PB4 / 绿 PE6 / 蓝 PE5，低电平点亮）按红→绿→蓝循环，验证 GPIO 输出正常。

### SD 卡与 FatFs（P0a-2 / P0b-1）

**卡**：SanDisk 16GB microSDHC，出厂即 FAT32 + 32KB 簇，未重新格式化。
**接口**：SDMMC1 四位（PC8~PC11 = D0~D3、PC12 = CK、PD2 = CMD），SDMMC 内核时钟取 PLL1Q = 192MHz。

实测输出：

```
FATFS mount: OK
SD card    : OK
SD type    : 1
SD version : 1
SD class   : 1461
SD blockNbr: 31116288
SD blockSz : 512
SD capacity: 15193 MB
FATFS free : 15189 MB   (cluster = 64 sectors)
FATFS dir  : [FILE] CG_TEST.TXT
FATFS write: 34 bytes -> CG_TEST.TXT
FATFS read : OK, content matches
```

两处读数需要说明，避免误读：

- `SD class = 1461` 不是速度等级，是 CSD 里的 CCC 命令类位图（0x5B5）
- 未列 `CardSpeed`：`HAL_SD_GetCardInfo()` 不填该字段，打印它读到的是未初始化的栈值

**结论**：挂载 → 写 34 字节 → 读回逐字节比对一致；剩余空间读数 15189 MB。

### 心跳日志落卡（P0b-2）

**验证方式**：主循环每轮把 `cycle N` 追加写入 `0:/LOG.TXT`
（打开模式 `FA_WRITE | FA_OPEN_APPEND`），每轮同时打印文件当前大小。

实测输出（节选）：

```
cycle 9
LOG size = 4729 B
cycle 10
LOG size = 4739 B
```

**判据**：每轮增量应等于 `6 + 十进制位数 + 2`（`"cycle "` 6 字节 + 数字字符数 + CRLF 2 字节）。

| 轮次 | 增量 | 依据 |
|---|---|---|
| cycle 1 ~ 9 | +9 字节 | 数字 1 位 |
| cycle 10 起 | +10 字节 | 数字 2 位 |

实测与判据完全一致，说明追加位置、写入长度、行尾都正确。

**对照实验（异常路径）**：把打开模式改成 `FA_CREATE_ALWAYS` 复测，
文件大小固定在"当前一行"的长度（cycle 5 时 9 字节、cycle 10 起 10 字节，不随轮次累积），
证实每轮被清空重写；改回追加模式后恢复增长。这条对照是判定追加语义的依据。

### 免读卡器的验收手段

开发阶段板子不接读卡器，SD 卡相关代码用两条固件内诊断输出验收：

1. 挂载完成后 dump 日志文件开头 200 字节 —— 确认内容，不只看大小
2. 每轮打印日志文件当前大小 —— 确认追加语义
