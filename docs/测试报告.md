# 算法验证报告

## 验证方式

`code/App/` 下的模块不引用任何硬件头文件，只依赖 `stdint.h` 和标准数学库，
因此可以在 PC 上编译运行。验证用 GCC 11.4（WSL Ubuntu 22.04）完成：

```bash
cd code/pc_test
bash build_run.sh
```

测试程序为每个场景构造一段输入序列，逐步喂给状态机与诊断模块，
检查状态迁移和目标故障码是否与预期一致。每项断言打印期望值与实际值。

这类验证只能覆盖逻辑正确性。时序、噪声、采样误差、总线竞争等问题
必须上板之后才知道，届时需要重做一遍硬件在环测试。

## 场景 1：三级告警与迟滞恢复

**输入**：负载温度每秒上升 5°C，从 25°C 升到 80°C；再每秒下降 5°C 回到 30°C。
两路温度探头读数相差 1°C，不触发漂移判据。

**预期**：升温时 NORMAL → WARN → ALARM → EMERGENCY；
降温时按迟滞阈值反向迁回。

**实测**：全部按预期迁移。值得注意的是 WARN 的触发点。

温度在 t=5s 时达到 50°C，超过 45°C 阈值，但状态直到 t=7s 才切换为 WARN——
因为向上迁移需要连续 3 秒满足条件。这是去抖机制在起作用，
符合设计意图：单次超限不报警。

## 场景 2：加热回路断路

**输入**：占空比 50%，电流 0A，持续 3 秒。

**预期**：电流低于 0.05A 且占空比大于 0 的时长累计到 2 秒时，报 `加热回路断路`
并锁存。

**实测**：在 2.0s 处触发，与判据阈值一致。超时参数 `CFG_I_OPEN_MS` 单位是
毫秒，实际物理意义是"确认断路需要观察的时间"，设为 2000 是权衡结果：
设太短容易把瞬时的接触抖动误判为断路，设太长则断丝时加热已经停了很久。

## 场景 3：过流

**输入**：占空比 100%，电流 3.2A。

**预期**：超过 2.5A 立即触发，不经去抖。

**实测**：单步即触发。过流不设去抖是有意的——短路电流没有"观察"的余地。

## 场景 4：MOS 击穿直通

**输入**：占空比 0，电流 0.5A。

**预期**：报 `MOS 击穿直通`。

**实测**：单步触发。这个判据的工程意义在于：MOSFET 击穿后漏源短路，
即使栅极命令为低，回路仍然导通，加热不会停止。此时唯一的保护手段是
外部温控开关和保险丝，固件的责任是尽早发现并告警。

## 场景 5：温度探头漂移

**输入**：负载探头 70°C，局部探头 59°C，占空比 0。

**预期**：两路都超过 45°C 且偏差超过 5°C，报 `温度传感器漂移`。

**实测**：单步触发，偏差 11°C。

判断条件要求两路都超过 45°C 是有原因的：如果有一路是常温，
也有可能是那一路的探头坏了而不是这一路。要求两路都进入预警区，
是为了把"真实过热但两路读数有正常差异"和"探头失效"区分开。

## 场景 6：散热异常

**输入**：占空比 80%，电流 0.5A，温度每秒上升 2.0°C。起始温度 30°C。

**预期**：模型预测温升速率约 0.84 °C/s，实测 2.0 °C/s，残差 1.16 °C/s，
超过 0.5 °C/s 的阈值，报 `散热异常`。

**实测**：触发，实测温升速率 2.000 °C/s。

**这一版判据改过一次。** 最初写的是"温升速率超过 0.3 °C/s 就报警"，
结果场景 1 的正常升温（5 °C/s）直接触发了误报。
问题在于固定阈值没有物理依据——温升速率取决于加热功率和负载热容，
不是可以拍脑袋定一个常数的事情。

改成一阶热模型残差之后，判据比较的是"实测温升"和"由电流推算出的功率
所应产生的温升"之间的差异，不再依赖绝对的速率数值。

## 场景 7：元件老化趋势

**输入**：占空比 50%，电流恒定 0.5A，负载电压从 5.00V 以每步 0.01V 缓慢上升。
40 步之后 R 从 10.000Ω 升到 10.780Ω。

**预期**：阻值斜率超过 0.05 Ω/s 时报警。

**实测**：斜率 0.2000 Ω/s，触发 `元件老化趋势预警`。

判据只在"占空比大于 0 且电流大于 0.05A"时才计算阻值，因为占空比为 0 时
电压读数没有意义，强行算 R 会得到无意义的数值把趋势窗口污染掉。

## 场景 8：加热闭环

**输入**：一阶热模型 `C·dT/dt = P − k·(T − Tamb)`，C = 9 J/K，
k = 0.08 W/K，Pmax = 10W，环境温度 25°C，目标 50°C。仿真 200 秒。

**预期**：收敛到目标温度附近。

**实测**：

```
   时间(s)   温度(°C)   占空比(%)
        0      25.00      100.00
       20      45.35       93.25
       40      49.00       19.95
       60      49.04       19.24
      100      49.04       19.24
      180      49.04       19.24
```

稳定在 49.04°C，与目标相差 0.96°C。

这个稳态误差是纯比例控制的固有特性。比例控制要维持输出，就必须保留一个
非零误差。若要把误差压到 0.5°C 以内，需要引入积分项。

目前保留纯比例是有意的：积分项在故障注入测试中容易积累，一旦温度
被外部因素（比如人为拔掉加热线）拉低，积分器会因为长时间误差而饱和，
恢复时产生大幅超调。对温控这种响应慢的系统，超调比稳态误差更危险。
后续如果实测发现 1°C 的误差不可接受，再考虑加积分并配合抗饱和处理。

**关于参数 C 和 k**：这两个值目前是从 10W 水泥电阻的典型热物性估的，
不是实测辨识的。上板之后需要用恒定功率加热并记录温度曲线重新拟合，
否则判据 5 的残差基准不准，会直接影响误报率。这是上板后的第一项测试任务。
